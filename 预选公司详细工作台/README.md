# 预选公司详细工作台

在协作仓库根目录运行 `python "预选公司详细工作台/start.py"`，打开 [候选登记](http://127.0.0.1:8781/)。Windows 的 Python Launcher 可用 `py -3`。需要 Python 3.10 或更新版本，核心操作使用仓库内固定版本的 Companybench，原件入库与手工核验无需额外 Python 包。可选 `pypdf` 仅用于 PDF 自动文字索引。

## 从候选到报告

1. 登记公司名称、市场、证券代码、行业适配和预选理由。市场与代码形成独立工作区标识，例如 `SSE-600000`，港股代码保留前导零。
2. 在「待确认」卡片填写实际确认人、确认依据并确认研究对象。负责成员据团队分工执行。对象确认只开启该公司工作，事实核验与报告签署各走对应流程。
3. 点击「创建独立工作区」。进入原生工作台，在「材料与来源」导入并登记原件。「事实核验」逐条定位原件并核对期间、单位、口径和主体；如修订来源或计算前提，由 ReviewStore 重新判断记录当前有效性。
4. 用「研究与合同」保留制度与商业模式底稿，在「计算与情景」保存预测和估值，在「报告与交付」生成 Markdown 与证据交接包。最终 Markdown 按 [报告留存处](../报告留存处/README.md) 的合并流程提交。
5. 从候选卡片进入「关联已有资料」，检索五家公司可公开研究的来源或成果编号，记下引用用途。原研究的 Fact、人员身份、估值参数和签署留在原工作区。新研究对读原件后以本地实际事件建立新的当前 Fact。

工作台读取 [共享运行时与模板](../shared/README.md)，无需在每个公司目录安装一套程序。新增的候选、确认、工作区和研究记录默认放在本目录的 `runtime/`，随本地存储保留。每家公司独立存放 `sources/`、`work/`、`evidence/` 和 `outputs/`。原件、报名信息、实际签署和密码不进入协作分支。确认误填时请保留本地原记录并交负责人处理；新建操作会保护同市场、同代码的现有目录。

[三公司工作台](http://127.0.0.1:8780/) 启动后，资料检索页的公开成果链接可直接打开。两套工作台均运行在本机回环地址。换端口可传 `--port 8782`；图册和已有成果使用其他端口时设置 `--research-port 端口`。隔离测试或独立团队目录可传 `--data-dir 路径`。在工作区侧栏「候选与工作区」可返回登记页。

验收记录见 [浏览器验收](acceptance/receipt.json)。
