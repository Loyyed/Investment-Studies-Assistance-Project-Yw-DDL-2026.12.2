## 找资料时按这四层走

1. **读论证**：`docs/long-atlas/公司键/chapters/01.md` 至 `07.md` 是长篇正文源。`case.md`、HTML 与 JSON 是同源生成物；需要改长篇时先改章源，再重建。
2. **查数字与模型**：`docs/cases/公司键/` 的 `history.csv`、`interim.csv`、`inputs.json`、`parameters.csv`、`forecast.csv`、`model.json` 及各专项表。历史数、算术、情景和估值分开读。
3. **回原件与核验**：从 `evidence-index.csv`、来源清单和各公司账本定位。冷启动带来的 Fact 快照不代表本机已恢复原件；实际有效状态按该公司的 ReviewStore 判断。
4. **写团队稿**：先在个人分支起草 Markdown，按[报告留存规则](../../../../报告留存处/README.md)交入 `报告留存处/`；团队复核和确认后再走合并、排版。

完整导航见[人类阅读使用流程](../../../../人类阅读使用流程.md)。

## 约 40 页报告如何接续

以一个可证伪的投资命题串起商业模式、竞争、治理、历史财务、预测、估值和反方。复用本项目的[课程要求与页数工作预算](../../../analysis-preparation/requirements.json)，再按选中公司的素材地图取舍，不把五家报告拼接成一份。

用户要求约 40 页；仓内预算合计 40 页，但它假定封面、来源与附录计入。最终页数统计口径和成员分工仍待团队确认。Markdown 阶段先约定论证及图表预算，不能将 MD 字数直接认定为 PDF 页数。

后续报告采用 `YYYY-MM-DD_市场-代码_题名_vX.Y.md` 命名，记录作者、草稿状态、信息时点、源模型与待审项。最终稿统一转换 PDF。按本成员最新排版偏好：明确中西文字体，完整标题使用同一字体和字重；表题居中置于表上，图题居中置于图下；实际渲染后检查字体、表格和分页。源 Markdown 与修订历史保留。
